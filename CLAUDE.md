# Empirical study of scoring rules on multiple-choice TruthfulQA

Research repository and report: what multiple-choice TruthfulQA rewards, studied with the base model's
likelihood, DoLa in two configurations, per-question DoLa-static (code name `fanda`, formerly FAnDa; one of the
studied rules, not a proposed method) and self-evaluation, P(True), on Qwen2.5-3B-Instruct and seven other small
models. PAnDa, an earlier block-wise method, was dropped (2026-11-14): keep its decoder code
(`src/truthfulqa_scoring/decoders/panda.py`; saved exploration runs use it), but leave it out of the report and the
README. Renamed on 2026-11-15: the package `panda` → `truthfulqa_scoring`, the report `fanda_report.tex` →
`report.tex`, and the local folder `PAnDa` → `truthfulqa-scoring-rules`. Do not rename the scoring rules' code names
(`fanda_frozen`, `panda_switch`, ...), the experiment folders or the `PANDA_SINGLE_PASS_TF` variable: saved runs and
docs depend on them. If the folder is ever moved again, `.venv` must follow: it stores absolute paths (launcher
scripts in `.venv/bin/`, the `activate` scripts, the editable-install `.pth` and `direct_url.json`); rewrite them
with `sed` or recreate it with `bash scripts/setup_env.sh`. Saved runs' metadata keep the old path; that is a record
of where they ran.
**The GitHub repository is public**: never commit `archive/`, course material, model weights, datasets,
tokens or `.env`.

## Results and terms

- Results are read only from `results/experiments/<exp>/runs/<run>/*_summary.csv`, `*_raw_predictions.csv`
  (one row per question, `example_idx`), `*_metadata.json` and the analysis outputs (`analysis/`, `cross_model/`).
  `python scripts/summarise_runs.py` prints every saved run.
- `docs/experiment_log.md`: every experiment, its result and the known issues. Update it after each new run.
- **Terms:** prose (report, README, docs, commit messages) uses standard machine-learning terms only, never project
  vocabulary (anchor, jitter, persistence, view, regime, arbitration, ...). Do not reintroduce "FAnDa" in prose
  except as the former name.
- `docs/glossary.md`: code names and older-note words → standard terms. Do not rename identifiers: saved runs and
  figure JSON depend on them. Watch out: `fanda` means re-selection every 4 tokens in exp7–exp10 and a fixed layer
  in exp11/exp18.
- Question sets: the 50-question subset (seed 42) is the **development** set (every layer-contrast choice was made
  on it); the other 767 are the **held-out** set (exp19); exp20 splits all 817 into 417 **exploration** and 400
  **confirmation** questions (seed 20261115). State which set each choice was made on.
- exp14 "manual" scores (at the tag `pre-cleanup-2026-11`) were written by Codex (an LLM). Say so wherever they
  are used, unless a person reviews them.

## Environment

- **GPU runs happen on this PC, in WSL Ubuntu** (RTX 5070, 12 GB), in `.venv` (a Linux venv on the Windows
  drive, created by `bash scripts/setup_env.sh` from `requirements-lock.txt`; no system site-packages). Run in
  `tmux`. Model and dataset caches are in WSL's `~/.cache/huggingface` (the eight study models, the HINT model and
  the TruthfulQA arrow file are cached there).
- The June 2026 runs used a `.venv` whose torch came from the system Python (version lost; package list in
  `docs/environment_2026-06.txt`); that venv is in `archive/venv-2026-06-no-torch`. Pins in `requirements.txt` match
  its versions, plus torch 2.9.1 + cu128.
- On the Windows side, run the plotting and summary scripts with
  `uv run --no-project --with matplotlib --with pandas --with numpy python <script>`.
- Run every script from the repository root (plot scripts use paths relative to it).
- Keep `huggingface_hub` < 1.0: newer versions reject the dataset id `truthful_qa` (they need `namespace/name`).
- New runs record their environment in the metadata (`collect_environment` in `results/experiments/common.py`).
